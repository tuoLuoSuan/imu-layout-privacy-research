# S5标准版：安装与第一条2秒记录

最新进展：用户已确认源码最小0.0.2启动/点击/退出正常；采集版0.1.1源码格式也报告首页与2秒自动保存正常，但原始导出未收，不能当原始数据验收。**下面旧0.1.0流程继续暂停**，只按[0.1.1两秒协议](../protocols/2026-10-15-s5-acquisition-2s-source.md)导出这条原记录，不重新采集。两旧失败包不再打开，原件/失败记录保留。

历史暂停：0.1.0采集版和最小启动0.0.1均被用户报告整表黑屏卡住，下文旧包流程继续暂停。DS021后0.0.2和0.1.1的后续观察见上段；原始序列、单位与频率未核，不把页面成功当硬件数据通过。

日期：2026-10-15。用户报告系统3.102.036，已用小米运动健康配对，AstroBox显示S5且已连接。当前只完成连接状态的用户确认；安装、传感器与真实导出尚未验收。

## 1．把新RPK放到手机

电脑文件：`collection/watch-s5-probe/dist/org.imuresearch.s5probe.release.0.1.0.rpk`。以最终构建验收报告的存在性及哈希为准。

使用USB文件传输或现有本地文件传输方式，复制到手机Download。RPK是手表安装包，不用在手机文件管理器里当APK打开，不更改文件后缀。不要用旧9Pro包覆盖S5测试，也不用把手机IMU采集APK装到手表。

## 2．从AstroBox推送

1. 打开AstroBox，选已连接的S5。
2. 进入“应用／快应用”页，点“＋”，选择本地RPK；也可从“队列→＋→应用／快应用”选本地文件。菜单名以当前版本实际页面为准。
3. 若进入队列，点开始推送，等完成；在手表应用列表打开“S5 活动采集”。
4. 看首页标题是否为“活动采集·S5”，开始/停止/设置/导出入口是否可见。先不录长数据。

如出现安装/签名/接口错误，保留完整报错。当前已经连接，不需要重新解除配对；若流程转为恢复出厂/清数据，停在那一页核对。登录和账号验证只在用户手机本地完成，不传密码、Authkey或序列号。

## 3．首条只录2秒

1. 默认静止、2秒；若已改过，在“设置”选“静止→2秒→返回采集”。
2. 手表保持前台可见，放稳或佩戴后手臂放在桌上，点开始。
3. 等自动停止、保存，观察条数与XYZ是否有数字。静止含重力时不要求XYZ全为0；game是请求档位，不能说已经达到50Hz。
4. 等“已保存…条，可导出”，不要立刻另开记录。若显示接口失败/保存失败，先报原文，不把失败当通过。

## 4．导出并核对原件

1. 点“导出二维码”，用手机相机完整拍下每页。可点“自动/暂停”，每2秒翻页并循环；拍到全部页，最好多一轮，避免反光与失焦。
2. 把原视频或各页清晰图片传到电脑。
3. 双击`collection/watch-s5-probe/导出CSV.cmd`，选择视频/图片。输出JSON、CSV和quality.json在该模块recordings下，已有输出拒绝覆盖。
4. 缺页或CRC错误必须补拍，不能补值或手改记录。原视频保留。记录内应是S5/standard/3.102.036、未知单位、回调时钟和真实条数，不能出现9Pro设备标签。

导出兼容旧IMU9P协议前缀，但记录的设备身份是S5。该光学路径只用于短试，不用于证明正式连续数据出口或波形精度。

## 5．后续分阶段

首条验收后，再逐条做10秒静止、转腕/摆手、走动，每段先导出再下一段；检查读数变化、间隔、时钟和单位/轴向线索，不靠一个静止模长直接定单位。之后分别测试前台、熄屏、切出，保留独立会话与实际状态时间。正式通信、跨端同步和持续性另行设计；不先录半小时或接雷达联采。

## 0. 一页摘要

- **任务**：一部普通安卓手机（六轴：加速度计 + 陀螺仪，**无磁力计**）在房间里走一段，输出房间的二维平面图（墙、门、床、桌柜、椅子）。
- **已有**：完整流水线跑通。三条独立录音对同一房间给出一致的床 IoU 0.87 / 0.84、桌柜 IoU 1.00；5 类动作分类跨会话 0.95 / 0.87；靠 `seated` 锚点把椅子定到 0.40 m。
- **核心观察**：只用几何（占据证据）时，**大片贴墙家具（床）能定到 IoU 0.81–0.82，但实例边界不可分**——桌柜只拿到 0.33–0.36，因为它与上方没人走过的空墙并成了一整条 0.6 × 4.0 m 的矩形。
- **待定的主张**：**动作事件提供切分「不可走区域」的语义锚点；占据 + 动作缺一不可。** 这一条还差最后一个数（动作锚点接入后的桌柜 IoU）。
- **文献位置**：IMU→布局本身已非新工作（IMU-to-4D 已做）；CoGuide 已做轨迹→户型。空档在「**实例级切分**」这一环。

## 1. 任务与目标口径的演变

1. 最初：用 IMU 轨迹**验证**一个由雷达点云给出的家具布局。
2. 用户 2026-11-05 明确（m03232）：**输入 IMU，输出一张二维平面图；家具尺寸作为已知先验**（床就用现场那张床的尺寸）。
3. 进一步收敛（m03280）：**把轨迹做稳定、能识别哪里做了什么动作，做一次把这间屋子还原出来**，剩下交给电脑模拟。
4. 再进一步（m03726）：**家具尺寸给个大致就行——靠墙就靠墙、尽可能大、但不要超过人走的轨迹线。**

第 4 条实际上把「尺寸先验」降级成了「形状常识」，这是本文档后面消融实验的出发点。

- 六个卷尺数：S 到左墙 82.5、S 到门墙 20、床到右墙间隙 14.5、桌柜到左墙间隙 5、桌与柜连体、床高 50。
- 定稿坐标（点云帧，x 0–2.84、y 0–4.045）：
  - 门：y = 4.045，x 0.395–1.17

  - 桌柜：x 0.05–0.65，y 0.00–2.10
  - 起点 S = (0.825, 3.845)
- **参考真值来源**：Livox MID-360 静态扫描（八条 bag，四站融合，190,244 点）。点云**只用于最后打分**，不进任何推断环节。

- **尺度必须被推断，不能被假设**：同一房间同一人，尺度跨 0.75–1.41。

### 3.2 布局推断（几何）

规则：**房间减去人体半径（0.35 m）内的走过区域，剩下的连通块就是家具**；矩形贴墙、尽可能大、不越过轨迹。

- 仅几何（无尺寸、无墙先验）：
  - 床 IoU **0.82 / 0.81 / 0.81**（004 / 013 / 011），推出面积 3.4 / 2.7 / 3.2 m²，真实 3.18 m²
  - 桌柜 IoU **0.33–0.36** —— 与上方空墙并成一条 0.6 × 4.0 m
- 加尺寸先验 + 墙先验：床 0.87、桌柜 1.00（但这是先验给的）
- 加「两件家具联合放置、互不重叠」（**仍不给墙先验**）：柜子自己落到 (0.00, 0.00)，IoU **0.85**；床 0.66–0.91

### 3.3 动作分类

- 旧模型（9 类，裤兜训练）：在手持数据上 `lying` 召回 0、最高置信度 0.98 出现在错误的 `upright` → **跨握法失效**；纯走路录音也会报家具动作（事件分类器不是检测器、无 null 类）。
- 新方案（5 类：walk / seated / lying / cabinet_interaction / other）+ **姿态编码**（坐时手机竖直贴腿、躺时平放大腿）：
  - 跨会话：008→009 **0.95**，009→008 **0.87**
  - 姿态证据：acc_z 均值中位 walk +0.03 / seated −0.29 / lying −0.94
- **重要局限**：手机时间戳无墙钟，标签是用「A 轮语音脚本 + 活动节奏反推时间偏移」（008 9.4 s、009 8.7 s）得到的**推定标签**，不是人工核实真值。
- 锚点效果：`seated` → 椅子 **0.40 m**；`lying` → 床 1.22 m；`cabinet` → 柜 2.46 m（后两者受 009 轨迹 43.9% 穿床拖累）。

### 3.5 试过但没用的东西（负结果）

- **yaw 常值漂移修正**（尺度锁 1）：闭合误差 12 条全降（004 0.08→0.04 m，013 0.50→0.33，006 1.14→0.49），但**家具侵入一半变差**（006 8.5%→55.9%，009 43.9%→80.5%）→ 闭合变好 ≠ 形状变好。
- **曼哈顿约束**（直段对齐墙）：同样只改善闭合，不改善摆放。
- **重力对齐**（把手持姿态旋到裤兜姿态）：最高置信度仍 0.71，零窗 ≥0.75。
- **「覆盖面积最大」作为拟合判据**：欠定——004 有 **339 组**（旋转, 尺度）都能让轨迹 100% 在房间内。

### 差距（我们的位置）

- IMU→布局：**59 已经做了**，而且规模大得多（多数据集、LLM、2–3 IMU）。
- 轨迹→户型：**16 已经做了**，而且是可引用的形式化（逆问题 + A* 正算子 + 代理似然）。
- 动作/接触→物体：**58、30 都做了**，但它们是**把现成物体放进去**，不做「不可走区域的实例切分」。
- 语义地图：**43 做了**，但语义来自用户打字。

**空档**：没有任何一篇处理「几何给出的不可走区域是一整块、边界在哪断开未知」这个问题，也就没有报过这个失败模式。我们的柜子（0.33 vs 床 0.82）就是这个失败的直接测量。

## 5. 提议的科学定位

> **占据证据回答「哪里不能走」，动作证据回答「这是什么、到哪为止」；二者相乘才得到实例级的家具布局。**

可证伪命题（也是消融表最后一行）：

- 去掉动作 → 实例边界错（柜 0.35）
- 去掉几何 → 动作只给点、不给范围（椅子 0.40 m 但没有尺寸）

形式化（提议）：
```
max_{T, F}  Σ_{c∉F} log p_free(c | T)          # 占据似然（轨迹变换 T）
          + Σ_k log p(a_k | c_k, F)            # 语义似然（动作锚点落在家具边缘附近）
          + Σ_F log p_shape(F)                 # 形状先验（轴对齐、贴墙、尺寸分布）
```
求解：① 在 (θ, s) 上搜对齐（已实现）② 房间减人体半径得连通块 ③ **用动作锚点切分连通块**（未实现，是关键一步）

## 6. 已知局限（写论文前必须处理）

1. **单个房间、单个人、13 条录音**；无跨人、跨房间证据。
2. **动作标签是推定的**（活动节奏反推偏移），不是核实真值；需要在每次录制开头加**同步标记**（用力摇三下手机）把它变成测量。
3. **`other` 类在现有录音里只切到 1 个窗**，等于没有背景类，假阳性率无法评价。
4. **无磁力计** → 无绝对航向，全局旋转/尺度不可辨识；这是硬件事实，不是算法缺陷。
5. 当前没有正式的「开发/验证/测试」划分（只有两条互相测的最小验证）。

## 7. 请 GPT 明确回答的问题

1. **这个主张够不够撑一篇会议论文？** 即「动作锚点切分占据连通块」这一条，配 A–E 消融表 + 单房间数据。如果不够，最短的补充是什么（多房间？多人？A* 似然？）。
2. **要不要引入 CoGuide 的 A* 正算子？** 具体做法：给候选布局跑 A* 生成「人应该怎么走」，与实测轨迹比相似度，替代现在的「覆盖面积最大」打分。这能解决我们 339 组解欠定的问题，但会引入 A* 实现与超参。值得做吗，还是用更轻的约束（如曼哈顿 + 锚点）就够？
3. **SUMMON 的两项损失能否直接照搬？** `L_contact`（锚点到家具表面距离）+ `L_pen`（轨迹穿入家具的深度）。我们的锚点是「坐下/躺下/开柜门」的事件中心，不是身体顶点，这样定义接触项合理吗？
4. **投什么 venue**？以当前规模（单房间、单被试、手机六轴、无磁力计），IMWUT / UbiComp 是否比 CVPR/ICCV 更合适？如果是 IMWUT，评价口径要换成什么（部署性、误锚点率、可用性）？
5. **标签问题怎么表述最稳妥？** 我们没有视频真值，只有脚本 + 时间偏移推定。是（a）加同步标记重录，（b）补视频，还是（c）在论文里明确写成「script-conditioned labels」并只报相对比较？
6. **要不要把「无磁力计」写成贡献的一部分？** 即：在只有六轴的商用手机上，报告哪些先验是必要的、哪些可以省掉（我们的消融正是这个）。这是诚实定位，但会不会显得像在解释不足？

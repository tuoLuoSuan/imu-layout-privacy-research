# 交接：换范式——从「模板匹配」到「自由空间 + 锚点约束的逐物体网格放置」

日期 2026-11-07。接收方：GPT。用户要求「必须要在其他的屋子里也跑通」。

---

## 1. 为什么换范式

之前的 `layout_core.py` 是**模板匹配**：假设「床+桌+柜+椅各一件、桌柜同墙、家具贴墙、椅子离桌 0.55 m」，然后只调旋转与平移。AI2-THOR 的 15 个场景里这些假设都不成立（桌柜同墙只有 9/15、椅心到桌最近边中位 0.00 m），所以怎么做都对不上。

试过一条中间路线：把柜墙与桌墙拆开、4×4 全枚举联合比较。结果是**覆盖率上去了但精度掉了**——oracle 从 5/15 无解变成 15/15 有解，但床误差从 0.50 m 退化到 1.41 m。说明放开墙组合只是让更多错误解变得可行。

## 2. 新范式：`layout_free.py`

不再给家具分配墙，而是**在 (x, y, 旋转) 上直接搜索**，用两类证据打分：

| 项 | 含义 |
|---|---|
| **自由空间** | 轨迹周围 0.25 m 标为「走过」；家具压到走过区域要罚 |
| **锚点约束** | 柜：站位到柜面前沿 ≈ 0.50 m（高斯，σ=0.25）；桌：椅心到桌最近边 ≈ 0.05 m（AI2-THOR 实测中位 0.00）；床：躺点必须落在床内；椅：坐点即椅心 |
| **贴墙奖励** | 家具贴着任一面墙给小奖励（软先验，不是硬要求） |

每个物体在锚点周围 ±1.6 m、两种旋转、10 cm 栅格上枚举，按 `W_ANCHOR·锚点项 + W_WALK·压到走过区域比例 − W_WALL·贴墙奖励` 取最优，按 柜→床→桌→椅 顺序贪心放置并禁止互相重叠。

参数：`GRID=0.10, WALK_R=0.25, W_WALK=3.0, W_WALL=0.35, W_ANCHOR=1.0, CAB_STAND=0.50, DESK_AT=0.05`。

**关键差别**：不假设贴墙、不假设桌柜同墙、不假设椅子离桌固定距离、不假设房间是长方形之外的任何东西。

## 3. 结果（15 个 AI2-THOR 场景，真值锚点构造）

| 臂 | 有解 | 床 中位误差 / IoU≥0.5 | 桌 | 柜 | 椅 |
|---|---|---|---|---|---|
| **oracle** | **15/15** | 0.54 m / 40% | **0.79 / 7%** | 0.53 / 0% | 0.00 / 100% |
| noise 0.10 | 15/15 | 0.53 / 42% | 0.93 / 5% | 0.72 / 0% | 0.11 / 78% |
| noise 0.20 | 15/15 | 0.54 / 36% | 1.07 / 3% | 0.73 / 1% | 0.22 / 36% |
| shuffle | 15/15（3 次无解） | **2.46 / 12%** | 2.35 / 1% | 1.76 / 0% | 0.63 / 34% |

### 与旧范式对比（oracle）

| | 模板匹配（第二版） | **自由空间（新）** |
|---|---|---|
| 有解 | 10/15 | **15/15** |
| 床 | 0.50 / 40% | 0.54 / 40% |
| 桌 | 1.00 / 0% | **0.79 / 7%** |
| 柜 | **0.33 / 0%** | 0.53 / 0% |

**换来的是覆盖率**：模板法在 5 个场景上根本无解，新方法**每个场景都能出图**。桌的精度也更好。柜变差了 0.2 m。

**shuffle 臂床 2.46 m 对 oracle 的 0.54 m**，说明方法确实用到了锚点的位置与语义，不是靠先验蒙的。

## 4. 还没解决的

1. **柜 0.53 m 仍偏大**，且几乎全在法向。锚点按「离墙 0.575+柜深」构造，而 AI2-THOR 的柜子常有 0.3–0.4 m 离墙间隙，求解端只能靠贴墙软奖励猜，猜不准。
2. **柜的 IoU 命中仍是 0%**：15 个里 13 个是 Shelf（0.13 m 深），0.5 m 的位移下 IoU 必然接近 0。**这是指标问题**，需要换成「中心误差 + 沿墙/法向分解」作为定位指标。
3. **桌的 0.79 m 仍偏大**：椅子与桌的对应关系在 AI2-THOR 里经常不成立（椅心到桌最近边 p90 = 1.92 m）。
4. **轨迹仍是直线拼接**、全标 walk，没有真正的可达路径与接触阶段。
5. **贪心顺序**（柜→床→桌→椅）有偏置，没有做联合优化。

## 6. 请 GPT 审的三件事

1. **贪心顺序是否引入了系统性偏差**：先放柜、再床、再桌、椅最后。柜压住的位置会让后面的物体无位置可放。是否该做联合优化（或至少多顺序取最优）？
2. **自由空间的半径 0.25 m 是否合理**：人走过去时身体两侧各占 0.25 m，但 AI2-THOR 的 agent 是一个点，轨迹本身没有宽度。这个参数直接决定「哪里能放家具」。
3. **柜的法向误差能不能从轨迹里解**：人开柜门时会站在柜前，静止段的朝向或站位分布也许能给出法向。现在完全没用这部分信息。

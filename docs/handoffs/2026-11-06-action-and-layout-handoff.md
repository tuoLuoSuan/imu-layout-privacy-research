## 3. 今天的动作分类（已完成，可交付）

### 3.1 做了什么

在 `output/lidar/2026-11-05-static-scan-002/` 下写了 **`analyze.py`**：一条命令从 zip 到动作时间线。

```
python analyze.py <IMU_xxx.zip> [输出目录]
```

内部：解包 → 调 `run_any_bundle.py` 跑冻结 RoNIN 得轨迹 → 训练 5 类随机森林 → 整段滑窗分类 → 打印时间线 + 出 `actions.png`。

### 3.2 关键结论：**不需要摇三下、不需要语音脚本**

上一轮的采集协议要求"提示音 + 甩手机三下"做时间对齐。用户 m00388 明确说实际录音是随便录的。
现在 `predict_whole.py` / `analyze.py` 直接对整段滑窗分类，**不做任何时间对齐**，仅靠姿态特征（坐=手机竖在大腿、躺=手机平在大腿）就分得开：

| 类 | acc_z 中位数 | 物理姿态 |
|---|---|---|
| walk | +0.03 | 手持自然摆 |
| seated | −0.29 | 竖直贴腿 |
| lying | −0.94 | 平贴腿 |

### 3.3 模型与精度

- 特征：`output/action-recognition/2026-11-02-accuracy-rebuild-001/dataset_ext.py` 的 `event_features` + `temporal`
- 分类器：`RandomForestClassifier(n_estimators=400, max_features='sqrt', random_state=0)`
- 窗：3 秒窗、0.5 秒步长、5 类（other / walk / seated / lying / cabinet）
- 训练数据：4 条按语音脚本录的对照轮 r1–r4（A,A,B,B 两种脚本），共 **340 窗**

**留一轮交叉验证（训练 3 轮 → 测第 4 轮）实测：**

| 留出 | 轮次 | 窗数 | 准确率 |
|---|---|---|---|
| r1 | A | 82 | **0.93** |
| r2 | A | 82 | **0.96** |
| r3 | B | 88 | **0.89** |
| r4 | B | 88 | **0.92** |

平均 0.925。各类召回稳定：lying 1.00（四轮全对）、seated 0.95–1.00、walk 0.79–0.97。
最弱是 cabinet（0.43–1.00 波动大），因为 B 脚本里"开柜"只有 7 个窗。

> ⚠️ 这是**同一天、同一个人、同一间房**的交叉验证，不是跨人跨场地的泛化证据。

## 4. 轨迹（RoNIN，冻结权重）

- 模型：作者预训练权重 `docs/reviews/evidence/2026-10-17-ds056-baseline-625a270a/`（`ronin-model.py` + `checkpoint_gsn_latest.pt`，SHA 校验）
- 输出：20 Hz，列 = t / x / y / speed；速度中位 0.14 m/s、max 1.05 m/s
- 速度是可信的：**从门口到椅子那段 RoNIN 量出 2.74 m，卷尺真值 2.75 m，差 1%**

### 4.1 一个必须记住的事实：**朝向在数学上定不出来**

没有磁力计 → 绝对朝向未知。旋转角是一个**纯自由参数**，只能靠房间/家具的先验去反解。
这不是实现缺陷，是传感器的信息缺口。

### 4.2 今天修掉的两个真 bug

**Bug 1：旋转矩阵方向写反。**
行向量右乘必须用 `[[c,s],[-s,c]]`（即 R 的转置），我写成了 `[[c,-s],[s,c]]`，等于朝反方向转了 2 倍角度。
后果：此前每一版"已经竖直"的图其实都是斜的；而且我用来"校验竖直"的断言也在用同一个错公式，所以自检永远通过。已改成转置并在 `vfix.py` 里断言校正后方向 = −90.00°。

**Bug 2：把"出门口那段必须竖直"当成了硬约束（更致命）。**
用户感觉"一开始是直直走过来的"，我就把首段强制掰成竖直向下。
实测：那段实际方向是 **−79.4°**（往右下），强行掰成 −90° 等于凭空转 11°，2.7 m 末端就偏 **0.5 m**。
**这才是此前所有"椅子差 0.5–0.6 m"的真正原因**，不是模型不准。

### 4.3 旋转角到底怎么定（当前做法 + 弱点）

不猜，用两条物理约束反解：

1. 整条轨迹必须装进 2.84 × 4.045 的房间
2. 从"躺下"那个点到对面墙，必须是一张正常的床（1.85–2.30 m）

两条同时满足的旋转角只有一个窄区间。59d570ee 上扫 −260°…−120°：

| rot | 在房内 | 椅锚点 | 椅误差 | 床尾 y |
|---|---|---|---|---|
| −205 | 83% | (0.49, 1.12) | 0.84 | 1.51 |
| −195 | 83% | (0.97, 1.10) | 0.37 | 1.73 |
| **−190** | **83%** | **(1.21, 1.12)** | **0.13** | **1.87** |
| −185 | 80% | (1.44, 1.16) | 0.11 | 2.01 |
| −180 | 64% | (1.67, 1.23) | 0.35 | 2.18 |

**弱点必须说清楚**：−205…−185 是一个**平台**，都满足两条约束，但椅子锚点在平台内移动了 0.7 m。
所以旋转目前是**欠定的（±8°）**，这是当前最大的单项误差来源。真正该做的是把"墙必须是直的两条正交方向"和"门只能在某面墙上"这类约束一起纳入，而不是只用一个床长先验。

## 5. 由动作反推平面图（按用户四条规则）

脚本 `layout_from_actions.py`：

1. 旋转 + 把起点钉在门口 S
2. 取每个动作窗口**最后 25%**（避开走过去的那几步）的平均位置作为锚点
3. 床：床尾线 = 躺下锚点的 y，向对面墙延伸，宽度 1.525
4. 桌/柜：靠椅子正对的那面墙（左墙），分界线由椅子高度 + 柜锚点决定
5. 椅：坐在椅子锚点上

### 5.1 最好的一条结果（59d570ee，56.5 s，14.12 m，首尾 2.5%）

| | IMU 反推 | 雷达实测 | 差 |
|---|---|---|---|
| 椅 | (1.21, 1.12) | (1.33, 1.14) | **0.13 m** |
| 床尾线 y | 1.87 | 1.96 | **0.09 m** |
| 床左沿 x | 1.31 | 1.17 | 0.14 m |
| 桌前沿 x | 0.60 | 0.65 | **0.05 m** |
| 柜顶 y | 0.76 | 1.05 | 0.29 m |

图：`output/layout-recon/s-59d570ee/floorplan.png`（左 IMU / 右雷达）

### 5.2 另外两条（表现差，供 GPT 判断鲁棒性）

## 6. 已知缺陷（未修，别当成已完成）

1. **旋转角欠定 ±8°** → 0.4–0.7 m 的横向误差。必须在方法层面解决（加入正交墙约束 / 门的先验），调参没用。
2. **柜/桌分界线不稳**（0.29 m 误差）。目前用椅子高度猜，没有独立证据。
3. **轨迹压进床角**（1130 点里 178 点在床矩形内）。这是漂移，不是家具放错；说明长距离闭合仍有问题。
4. **四条对照轮是脚本录的**，用户真实使用是随便录。跨"有无脚本"的域差异没有量化过。
5. **只有一个人、一间房**。0.925 的准确率不能外推。
6. **旧的几份结论已被证伪，不能再引用**：早前报的"椅 0.16 m / 躺 0.14 m"是 Bug 1 造成的补偿误差；`consistent_fit.py` 有真值泄漏（`BED=(1.17,1.96,2.695,4.045)` 写死在评分里）；`joint_place.py` 只枚举贴墙候选；`anchor_from_actions.py` 把 cue 偏移减了两次。

## 7. 能不能跳到下一步？

### 7.1 我的判断：**不能直接跳，但只差一件事**

用户想问的是"能不能不修这些、直接开始做模拟"。分两种情况：

- 如果"下一步"= **把已知房间渲染成 3D / 做模拟**（用户原话「剩下的就是电脑模拟的事情了」）→ **可以跳**。房间尺寸是卷尺实量的，家具是可以直接给的固定尺寸，不需要 IMU 提供。
- 如果"下一步"= **拿一条新录音自动产出一张图**（这才是"环境重建"）→ **不能跳**。旋转欠定这一条没解决，换一条录音就会崩（5.2 节两条已经崩了）。

### 7.2 差的那一件事

**把旋转从"一个自由参数靠先验猜"变成"被约束系统解出来"。** 具体建议：

用 4 个锚点 + 房间矩形做一个小规模联合搜索/优化，目标函数包含：
- 门必须在某一面墙上，且起点落门内
- 墙是两条正交方向（曼哈顿）
- 床靠墙、长边 1.9–2.2
- 桌柜共面（连体，用户和雷达都证实）
- 椅子在桌前 0.4–0.8 m，且正对桌子
- 所有家具不得压住轨迹（人不会穿墙 / 穿床走过去）

这套约束会大幅收窄旋转角，且**不需要任何真值输入**。做完之后，用 59d570ee 的 0.13 m 验证它有没有把平台消掉。

### 7.3 建议的优先级

| 优先级 | 事项 | 理由 |
|---|---|---|
| P0 | 旋转约束化（7.2） | 唯一挡住"换条录音也能用"的东西 |
| P0 | 再录 2–3 条首尾 < 3% 的 | 现在只有 1 条达标，没法验证 |
| P1 | 柜/桌分界线给独立证据 | 现在纯猜 |
| P2 | 跨人跨场地 | 0.925 不是泛化证据 |
| — | 修 6 节那三处旧脚本缺陷 | 只影响旧结论，不影响新链路 |

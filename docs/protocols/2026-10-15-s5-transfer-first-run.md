# S5普通传输首次真机步骤与反馈门

当前执行门（0.1.2）：用户0.1.1本地点击通过，但准备接收停在同步状态；离线查明旧组件为同步回调且spawn没有执行器。新候选保留API3/普通权限，显式生成四个异步任务入口。仅先覆盖更新手机插件，确认v0.1.2并点一次界面检查：须见“运行检查通过 · 可以准备接收”，仅次数增加不算。随后才点准备接收；“查询任务已启动，正在等待设备列表／授权…”与旧同步查询状态分开记录。若运行检查仍失败，不继续自动换包，先普通宿主诊断/评估另一普通出口。0.1.2未获用户反馈，不因二进制检查通过就声称真机修复。

最新反馈：用户报告0.3.1首页/退出正常、旧版记录可只读载入；插件0.1.0可导入/打开，但准备接收按钮文字完全无变化、无权限提示。尚无真正传输或原件。新增0.1.1浅色诊断候选：先保留数据覆盖更新插件，点一次“界面检查（无需手表）”，记录次数/反馈；同步检查也无反馈就停在此处，取普通宿主诊断。通过后才恢复下方准备接收/旧记录传输，不从头反复重装。圆标手表0.3.2只改图标/版本，可在保留数据下单独升级，不能把它当接收问题修复。

用户已报告0.3.0更新成功、首页正常；目前仍没有原始S5导出。先复用手机AstroBox2.2.0，不重新绑定手表，不卸载应用、不清数据。本轮按用户要求先传输，再测功能，最后合并DS。

1. 将最终核验的 `IMU-S5-Receiver-0.1.0-*.abp` 从电脑Download复制到手机。通过AstroBox本地插件/本地资源入口安装到手机宿主；不是推给手表。若要求重启，仅重启AstroBox。先确认插件能打开，遇到报错保留文字，不反复试装或改系统安全设置。
2. 插件界面正常后，再用既有普通AstroBox入口，保留数据覆盖更新 `S5-Transfer-0.3.1-source-*.rpk` 到手表。安装完成只开一次首页，核v0.3.1、菜单响应和正常退出。整表再卡立即停止。
3. 手机AstroBox保持S5连接，打开“IMU 腕部接收”点“准备接收”。本次按实际弹窗允许设备列表／项目App消息接收／确认消息发送，不申请固件或其它模块权限。保持手机接收页面前台亮屏。
4. 手表记录页先尝试恢复旧版最近一条，只读载入已保存的0.1.1两秒记录；有则直接选它→导出→蓝牙传输，不重录覆盖。保持手表传输页。若旧记录确实不存在，如实记录，之后另做明确标签的2秒测试记录，不能伪称旧数据已保留。
5. 观察手表进度、最终送达和手机已接收，原话保留。失败时保持原记录和接收缓存，先定位是连接/注册/消息/ACK/保存哪一层，不跳到长录。
6. 在手机插件点“保存完整会话到文件…”，将TXT存入Download。完成后再复制到电脑，由对应版本独立工具验CRC、条数、XYZ、时间源和间隔；只看到进度100%或文件名不当通过。
7. 链路及原件核验通过后，才测新采2秒、档位/标签贯通、回收/恢复（用专门测试记录）、30秒、1分钟前台；每步原件核验后再延长，息屏/切出另做短单变量。当前不安排批量长录。
8. 最后由Codex整理实际结果、失败与未验边界到一份DS交接。旧DS022仍只是0.3.0离线审查稿，本轮不提前当作新传输已验收材料。

若Android宿主拒绝ABP或API级别、系统保存不可用，不先改配对；记录具体错误，再评估同插件桌面AstroBox或另一条普通接收路线。官方运行环境列Android，但某些错误文档用“桌面端”措辞，不能凭单页提前保证用户手机可安装/导出。

## 1 候选池先验（wall_priors013）

`analysis/layout/wall_priors013.py`：`wall_gap(boxes,room)`、`pool_mask(entry,boxes,room,gaps)`、
`decode(..., wall=True)`。默认区间 `GAP={'bed':(None,0.12),'desk':(None,0.16),'cab':(None,0.16),'chair':(0.45,None)}`，
取值来自上表的上界加一点余量；`pool_mask` 在过滤后池为空时退回未过滤池，避免把房间判成不可行。

说明两臂只差这一个过滤。

两套 32 条合并（n=64）：frozen011 41/64 = 64.06%，wall012 45/64 = 70.31%，配对 39/2/6/17，

**结论（负结果）**：墙邻接用于修正轨迹时两次复现 +6.25 个百分点；用于过滤候选池时两套都不增反降

位姿误差约 0.2 m 就足以把一个本来正确的框推到 0.16 m 窗之外，过滤于是删掉「接近正确」的候选，
只留下贴墙但错位的解。这与 SUMMON 观察到的「可行但错误」是同一类失败。

## 5 传感器误差轴（sensor013）

同一 12 间房（11400–11411）、同一解码器（wall013）、同一基础信号实现，只按严重度 s 叠加
缓慢游走偏置（s^1.5）、额外白噪（max(0,s−1)）、标度与轴失准（4e-3·s / 2e-3·s）、时戳抖动（0.5 ms·s）。

### 5.1 配对阶梯

| s | 整屋 | 可行 | 手端加速度 RMS 误差 (m/s²) | 失败组成 |
|---|---|---|---|---|
| 0（原条件） | 7/12 | 10 | 0 | ok 10、search_budget_exhausted 2 |
| 0.5 | 3/12 | 3 | 0.0132 | ok 3、proposal_conflict 5、no_proposals 3、budget 1 |
| 0.75 | 2/12 | 3 | 0.0218 | ok 3、proposal_conflict 6、no_proposals 3 |
| 1.0 | 1/12 | 1 | 0.0315 | ok 1、no_proposals 5、proposal_conflict 4、frontend_error 2 |
| 2.0 | 0/12 | 0 | 0.0872 | frontend_error 12 |
| 4.0 | 0/12 | 0 | 0.2364 | frontend_error 12 |

「可行」列为没抛异常、也没耗尽搜索预算的房数。加速度 RMS 只到 0.013 m/s²（约 1.3 mg）时整屋已从 7/12 掉到 3/12：
这条链对真实手端没有余量，即使这个误差量级远小于文献里常见的器件标定残差。

### 5.2 plain 解码器对照

同样的 12 间房、同样的信号，把解码器换成冻结的 plain 链（`contact_loops011.refine` + `oriented_raw011.decode`，
即 013 墙先验之前的路径）：s=0 为整屋 8/12、F1 0.8583；s=0.5 掉到整屋 1/12、F1 0.0833（no_proposals 5、proposal_conflict 6）。
两条链在 0.5 档都崩，因此这一崩塌属于冻结链本身，不是 013 墙邻接池先验引入的脆弱性。

**读法限制（013 复核）**：两条链不是严格单变量对照。主链房间的流程是 `contact_loops011.refine` → `wall_refine012.refine`
→ 013 解码器；`plain` 臂用 `contact_loops011.refine` → 冻结 `oriented_raw011.decode`，因此它也做了接触回访；
而 `exp_sensor013` 的 wall 臂只做 `wall_refine012.refine`。所以 7/12 与 8/12 之间混着轨迹流程差异，
这一对照只能界定“崩塌不是新增池先验造成的”，不能当成换解码器的净效应。

### 5.3 机理是慢漂移而不是噪声幅度

对房间 11400/11402 做旋转不变的漂移探针（分子分母都用同一指标）：

| 房间 | s | 末端位移 / 真值 | 路程 / 真值 |
|---|---|---|---|
| 11400 | 0 | 0.61 / 0.56 = 1.10 | 73.4 / 72.6 = 1.01 |
| 11400 | 0.5 | 0.90 / 0.56 = 1.61 | 75.6 / 72.6 = 1.04 |
| 11400 | 1.0 | 0.72 / 0.56 = 1.29 | 78.7 / 72.6 = 1.08 |
| 11402 | 0 | 0.78 / 0.73 = 1.06 | 108.5 / 107.1 = 1.01 |
| 11402 | 0.5 | 1.26 / 0.73 = 1.72 | 117.6 / 107.1 = 1.10 |
| 11402 | 1.0 | 2.45 / 0.73 = 3.33 | 146.0 / 107.1 = 1.36 |

s=0.5 时路程只多 4–10 %，但末端位移已经错到 1.6–1.7 倍：游走偏置经二次积分后主要变成**慢变位姿偏差**，
把候选池推出接触环、或推出与房间外框相容的区域，于是表现为 proposal_conflict / no_proposals。
这也解释了为什么加白噪不是主因：白噪在积分里被平均掉，慢偏置不会。

### 5.4 极端档的逐项归因（2 间房 11400/11402、s=2，每次只加一项）

| 只加的项 | 11400 | 11402 |
|---|---|---|
| 偏置游走 | frontend_error | frontend_error |
| 额外白噪 | no_proposals | frontend_error |
| 标度/失准 | proposal_conflict | proposal_conflict |
| 时戳抖动 | ok，整屋命中 | ok，整屋命中 |

s≥2 时最先断的**不是几何求解器**，而是前端对初始静止段的判定：`inertial010.py:27` 的
`gyr < .009`（0.5 °/s）门在偏置游走 2 档下 720 个样本通过 0 个，于是 `inertial010.py:56` 抛
`ValueError: Initial stable handset period required`。

### 5.5 0.5 档的逐项归因（12 间，每次只加一项）

| 只加的项 | 整屋 | 可行 | 失败组成 |
|---|---|---|---|
| 无（s=0 基线） | 7/12 | 10 | ok 10、search_budget_exhausted 2 |
| 偏置游走 | 3/12 | 3 | ok 3、proposal_conflict 5、no_proposals 2、budget 2 |
| 额外白噪（s<1 时该项定义为 0，等价恒等） | 7/12 | 10 | 同基线 |
| 标度/失准 | 5/12 | 6 | ok 6、budget 4、proposal_conflict 2 |
| 时戳抖动（0.25 ms） | 7/12 | 10 | 同基线 |
| 四项叠加（sensor-sub 的 0.5 档） | 3/12 | 3 | ok 3、conflict 5、no_proposals 3、budget 1 |

慢变偏置游走单独一项就把整屋从 7/12 压到 3/12，与四项叠加的结果相同；标度误差次之；0.5 档的额外白噪为
零、时戳抖动只有 0.25 ms，两者单独作用与基线逐房一致。这与 5.3 的机理吻合：能穿过二次积分留下位姿偏差的
只有慢偏置，白噪被平均、抖动只改采样时刻。

**更正**：先在 2 间房（11400/11402）上做同一拆项时，四项单独作用都 ok 且整屋命中，据此曾写成"四项要叠加才失败"。
12 间全跑后该结论被推翻——那两间恰好对偏置不敏感。机理归因必须在整臂上做，不能取两间子样本。

### 5.6 无扰动可复现，0.5 档不能按剂量线性读

同一 s=0 条件下重复三次（`repeat013/a|b|c`），11400 与 11402 共六次运行全部 ok、整屋命中、F1 1.000：
冻结链本身是确定性的，上面各档的差异不是运行噪声。反过来，房间 11400 在 s=0.5 是 proposal_conflict，
在 s=0.75 反而 ok 且整屋命中。12 间单次实现下这不是平滑的剂量-响应曲线，而是余量极小、由具体扰动实现
决定的结果，因此只能报「某档还剩几间」，不能报「误差每增加多少就掉几间」。

这条结果限定了本方法的引用范围：层二、层三的全部数字都在 s≈0 的条件下取得，真实手端的标定残差必须先
跨过前端这道门、再跨过 0.5 档就已经出现的余量问题，才谈得上引用。

## 6 边界

- 三层都只在同一生成族内成立；真实数据仍只有一个宿舍单间（n=1）。
- 墙邻接是声明先验，不是从惯性数据估计出来的；换成真实房实测需要真实房的家具-墙隙测量。
- 「整屋全中」是四到七件家具的合取；±1 件即判失败，因此它不能与实例 F1 互相替代。
- 传感器轴的严重度是相对量，不是标定过的器件模型；层二、层三的成绩只在 s≈0 处可引用，s=0.5 已只剩 3/12、s≥2 全部在前端失败。
- 0.5 档的「四项叠加才失败」只在 2 间房上验证过；12 间的逐项表见 5.5 的补充运行。

# 这条轨迹能认出回访，房间编号仍未解决

更新于2026-10-29。研究仍围绕手机和手表记录能暴露多少活动与地点信息。本轮只检验其中的位置组件，没有证明手表增加了位置收益。

给定已有记录的7个停留窗口，只看未对齐到房间的手机模型位置，RoNIN在4次实际回访中都找到了对应的历史停留，EqNIO找对2次。计算没有使用房间图、地点名称、地点总数、路线脚本或雷达坐标。

这是1人1次记录的事后探索分析。停留窗口和时间对应条件由评价流程提供；算法不自动判断哪些停留是新地点，也不自动估计地点数。

## 结果与对照

| 输入或办法 | 四次回访匹配 | 同地配对排序AUC |
|---|---:|---:|
| RoNIN | 4/4 | 1.0000 |
| EqNIO | 2/4 | 0.6500 |
| 总选第一次停留 | 2/4 | 不适用 |
| 随机选一个历史停留 | 期望1.12/4 | 0.5000（常数配对分数） |
| 只看时间，选最近一次停留 | 0/4 | 0.26875 |
| RoNIN轨迹错开60秒 | 1/4 | 0.4125 |

7次停留共有21对，参考中5对同地、16对异地。AUC=1表示5对同地的距离都排在16对异地之前，不能解释成四区准确率100%。21对点共享访次，不是21个独立样本。

先前的9种时间情景全部保留：−3、−2、−1、−0.5、0、0.5、1、2、3秒。RoNIN均为4/4、AUC=1；EqNIO均为2/4、AUC为0.6500–0.6625。这些是软件假设下的敏感性情景，不是测得的跨设备钟差范围。

还枚举了组大小为3、2、2的105种无名分组。RoNIN只有1种分组达到观察到的AUC，EqNIO有23种。访次可交换性未经证明，这个条件排名不作为人群显著性或p值。

所有停留的动作标签相同，只看标签的配对AUC是0.5。如果攻击者已知路线脚本，它不看传感器也能答对对应关系；本轮没有把脚本交给计算函数。原动作识别结果仍按原会话单列。

## 四区扫描保留原结论

已知绝对位姿时得分明显高于相对条件。但把雷达对齐到房间只帮助评价者，不会自动让攻击者知道手机起点与朝向；它不等于模拟中的已知绝对位姿。

前次汇总的0.9500、0.2510、0.2500中位数来自族内、标签无误的48格子集。相对条件的后验熵下降不能直接叫测得的泄漏比特。本轮没有新抽样、改ε、扩网格或把四区失败改成成功。

## 复现范围

```sh
python -m unittest discover -s research/reference_evaluation -p 'test_*.py' -v
```

正式空间分数和真实房间排名保持null；物理精度、跨设备物理同步和跨人泛化未验证。后续需要独立记录检验这一回访结果，不能靠本条记录扩成普遍定位能力。

# 接触置信度：用事件时长当质量分数，方向是反的（030）

## 0 问题

IMU-HOI 那类工作在接触检测后面加一层置信度，把“不确定的接触”降权或剔除。我们的链没有置信度，
十四次接触一视同仁地送进精修与解码。要做这条，得先回答一个可测的问题：在**同一条录音、同样的
接触数量**下，按某个质量分数挑接触，比随机挑更好吗？

026 已经给出了“数量固定、位置变”的底座：固定 14 访次记录、把接触裁到 6 次，base 14 次 7/12
（F1 0.8135）、prefix 6 次 4/12（0.7274）、disperse 6 次 5/12（0.7028）、random 6 次 8/36
（0.6435）。本实验在这套底座上加第四个轴：**按置信度选，而不是按位置选**。

## 1 先试的两条口子，都不可用

**跨实现复现一致**。三次实现（offset 0/1000/2000）是同一段录音、只重抽手机噪声。读
`output/layout-recon/matrix023/off{0,1000,2000}/v14-s0.0/multi-<room>/result.json` 里的
`predicted_runs`（元素是 `[label, start, end]`，接触类别 `seated/lying/cabinet`），按时间重叠
50% 与 80% 两种口径统计：**12 间房的 14 个接触在三种实现里全部复现**。也就是说“这个接触是否稳定”
这件事在现有数据里没有方差，做不出可比的两个子集。

**跨源一致**。手机与手表都能报柜子。但 `analysis/layout/watch_cabinet.py:49 fuse()` 明确写着
`phone_cabinet_used=False`：手表是柜子的唯一来源，手机侧的柜子 run 在融合时被丢弃。于是“两个模态
都同意”只对柜子有定义，而且恰好被设计排除了。坐、躺只有手机一个来源。

剩下的、链上真的能拿到的质量信号只有**事件时长**。

## 2 设计

`analysis/layout/confidence030.py`。置信度 = 合格接触的时长（秒）。臂：

- `base`：全部 14 次接触，用于复现门；
- `dur11` / `dur9` / `dur6`：按时长降序取前 k 个；
- `rand11` / `rand9` / `rand6`：同 k 的随机子集，每个 k 三个种子
  （`random.Random(700000 + 10 * room + seed)`，seed 1/2/3）。

其余一切不变：同一段 14 访次、严重度 0 的录音（offset 0），同一门控陀螺前端、同一
`contact_loops011.refine`、`wall_refine012.refine`、`priorcost014.decode_arm(arm='base')`。

复现门：`base` 必须等于 `output/layout-recon/matrix023/off0/v14-s0.0/multi-<room>/result.json`
的 `all_instances_hit` 与 `f1`。

命令：

```
python -m analysis.layout.confidence030 --rooms 11500-11511 --jobs 4 --out output/layout-recon/confidence030
```

产物 `output/layout-recon/confidence030/confidence030.json`。

## 3 踩过的坑：把非接触 run 一起删了

第一版 `arm()` 写成 `sub = [runs[i] for i in keep]`，只保留被选中的接触，把 walk 与 other 段
全部丢掉。后果是 `walk_mask` 为空、解码器看不到行走证据，base 从 7/12 掉到 **3/12**、F1 0.6337。

判别法：base 臂是复现门，一旦它不等于存储行就不是实验结论而是接线错误。026 的 `subset()` 只过滤
接触类，其余 run 原样保留；照抄这一条之后 base 回到 7/12、F1 0.8135，与 026 逐位相同。

## 4 结果（12 间，整屋全中 / 平均 F1 / 平均接触时长）

| 臂 | 全中 | F1 | 时长 s |
|---|---|---|---|
| base（14 次） | 7/12 | 0.8135 | 10.41 |
| dur11 | 4/12 | 0.7786 | 10.97 |
| dur9 | 0/12 | 0.6431 | 11.35 |
| dur6 | 0/12 | 0.5486 | 11.74 |
| rand11（三 seed） | 5 / 7 / 7 共 19/36 | 0.8026 | 10.3–10.4 |
| rand9 | 5 / 6 / 6 共 17/36 | 0.7630 | 10.3–10.5 |
| rand6 | 5 / 4 / 5 共 14/36 | 0.7422 | 10.2–10.6 |

按房间比：`dur6` 相对同房间三个随机种子的 F1 均值，**2 间更好、9 间更差、1 间持平**。

## 5 机制：时长是类别代理，不是质量代理

数每个臂保留的接触类别（12 间平均）：

| 臂 | seated | lying | cabinet |
|---|---|---|---|
| base | 5.0 | 4.0 | 5.0 |
| dur11 | 5.0 | 1.0 | 5.0 |
| dur9 | 4.0 | 0.0 | 5.0 |
| dur6 | 1.4 | 0.0 | 4.6 |
| rand6 | 2.2 | 1.9 | 1.9 |

柜子的接触最长。按时长排序等于“优先保留柜子、先把椅子与床丢掉”。这是把空间证据压到一面墙上，
和 `prefix` 臂（只留最早的接触）同类的失败方式；随机子集反而保住了类别与空间的均衡。

结论：事件时长在这条链上不是可用的置信度。它能拿到，但它度量的东西（人靠在柜子前多久）与
解码器需要的东西（接触覆盖了几件家具、分散在哪几个方向）不是一回事。要把“接触置信度”做对，
分数必须来自**空间**（覆盖、方向、是否只落在同一面墙上），而不是来自事件本身的长短。

## 6 边界

- 只有 12 间房、一个严重度（s=0）、一个访次档（14）、一个 offset（0）；未跨批复现。
- 时长只是“链上现成可算”的信号。用检测器分数、真实接触概率或多模态一致性另做一套是另一个实验，
  本模块没有实现，也不宣称它们会失败。
- 交叉验证过的两条负数（复现一致、跨源一致）都是“信号没有方差/没有定义”，不是“信号错了”。
- 复现门只覆盖 room 11500 的历史行与 12 间 base 的整体计数，不覆盖每个房间的逐行 F1。

## 7 复现

```
python -m analysis.layout.confidence030 --rooms 11500-11511 --jobs 4 --out output/layout-recon/confidence030
```

约 6 分钟（4 进程）。JSON 里 `rows` 保存每房每臂的 `k`、保留类别计数、平均时长、状态与
`refinement` 明细，`summary` 保存聚合。

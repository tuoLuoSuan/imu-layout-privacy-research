# 落点效应不是某一个解码器的产物（034）

## 1 为什么做这一条

033 把几何层的落点干预搬进设备链之后，正文里留了一句限制：两批共用同一条链，估计不能外推到别的解码器。这句话对审稿人来说是个开口——他们会问，+28 个百分点是不是候选上限 128 加方向解码这套选择方式的副作用。这一轮把解码器本身变成一个变量。

## 2 设计

每间房按两种落点协议各录一次（同房间、同路线、同 14 次接触、同传感器种子、同前端、同两个精修器），两次录音各自用三个解码器解同一批 runs：

| 臂 | 候选上限 | 额外机制 |
| --- | --- | --- |
| `base` | 128 | 无（033 用的那个） |
| `basec64` | 64 | 无 |
| `p10c64` | 64 | 候选按墙面/支撑代价重排（λ=10） |

三个解码器都在 `analysis/layout/priorcost014.py` 的 `decode_arm` 里，033 已经用过 `base` 和 `p10c64`。房间集合同 033：开发 12 间 11500–11511，全新 64 间 11700–11763，共 152 个（房间 × 落点）单元。

复现门：`base` 在 11500 分散落点上必须给 1.0 整屋命中，实测通过（`placement034` 冒烟运行）。

## 3 结果

整屋命中（分散 / 重复）、配对差、精确 McNemar：

| 解码器 | 开发 12 间 | 全新 64 间 | 合并 76 间 |
| --- | --- | --- | --- |
| `base` | 7 / 8，−8.33 pp，p=1.0 | **48 / 30，+28.12 pp，p=1.2e-4**，[15.6, 40.6] | 55 / 38，+22.37 pp，p=9.1e-4 |
| `basec64` | 9 / 6，+25.00 pp，p=0.25 | **52 / 35，+26.56 pp，p=7.6e-5**，[15.6, 39.1] | 61 / 41，+26.32 pp，p=1.1e-5 |
| `p10c64` | 9 / 7，+16.67 pp，p=0.5 | **54 / 44，+15.62 pp，p=0.0129**，[4.7, 26.6] | 63 / 51，+15.79 pp，p=0.0042 |

平均实例 F1（分散 / 重复）：

| 解码器 | 全新 64 间 | 合并 76 间 |
| --- | --- | --- |
| `base` | 0.9304 / 0.8354 | 0.9120 / 0.8358 |
| `basec64` | 0.9223 / 0.8263 | 0.9133 / 0.8216 |
| `p10c64` | 0.9320 / 0.8600 | 0.9236 / 0.8587 |

同一批录音上三个解码器的整屋命中一致率：`base` 对 `basec64` 131/152，`base` 对 `p10c64` 123/152，`basec64` 对 `p10c64` 140/152。也就是说它们确实会在个别房间上翻转判断，但翻转的多少不足以改变落点对比的方向。

## 4 能说到什么程度

- 落点效应在三个解码器上同号且都显著（全新 64 间上 p 分别 1.2e-4、7.6e-5、0.0129），所以它不是候选上限 128 的产物。
- 量级依赖解码器：代价重排（`p10c64`）把重复落点那一臂从 30 抬到 44，效应缩到 +15.62 pp。这说明不同解码器吸收证据的能力不同，落点效应的一部分可以被更好的候选选择吃掉。
- 开发 12 间在三个解码器上分别 −8.33、+25.00、+16.67，符号不稳定，仍然是功效问题：这一档的不一致对只有 1–3 个。

## 5 边界

- 三个解码器同属一个家族（同一组候选生成器、同一个方向解码），换到别的论文的实现不在覆盖范围内。
- 只测了严重度 0、14 次访次、`prefix` 噪声协议。
- 一致率是整屋命中级别的，不是逐实例级别的。

## 6 复现

```
python -m analysis.layout.placement034 --ids 11500-11511,11700-11763 \
  --arms repeat,dispersed --workers 3 --out output/layout-recon/placement034
python -m analysis.layout.placement_stats034
```

产物：`output/layout-recon/placement034/placement034.json`（152 行，含每个解码器的命中与 F1）、`paired034.json`（三档配对的 McNemar、bootstrap、一致率）。每个单元的完整预测落在 `output/layout-recon/placement034/<placement>/multi-<room>/result.json`。

# S5 实机已见消息包装的最小适配

0.2.2真机截图已见：收到1、识别/保存/回复0；外层object共四个文本字段，含pkgName；其中一个其它字段为JSON文本，解码后根p精确为S5TX1。截图未暴露其它字段名或值，不把它们猜作payload/data/value，不宣称已经看到XYZ原件或确认回复。

主智能体依既有自主授权继续，不开子代理。选择有界的一层包装适配：仅当外层恰好四个文本字段、pkgName精确匹配已注册的org.imuresearch.s5probe时，在直接子文本中寻找根p精确S5TX1的JSON对象；必须恰好一个，原文本最多4096字节、外层最多8192。未知字段名没有协议含义，不递归遍历任意层，也不拼接或修复数据。零个/多个候选、错误包名、其它字段类型或数量均忽略。保留旧直接对象、JSON文本和data文本入口。

独立api4-envelope-adapter/0.2.3，旧0.2.2及之前源包不改。只替换receive的边界解包；核心receiver、存储、CRC、分片顺序/长度/冲突、同步和ACK规则字节不变，telemetry仍显示四计数和受控结构。SDK0.4.0/API4/WASI3/原生async、插件名/received/三普通权限不改，手机采集66/r2和手表0.3.4保持。

方案比较：猜出未显示的字段名依赖未核信息；递归扫描任意JSON扩大接受面；上述匹配已见结构并核包名/唯一性的单层适配足以修正已见边界，保留严格内容校验。

先用相同四文本结构合成用例复现旧解包忽略，再测试新适配原字节交付。错误包名、双候选、数量/类型变化、深层/过大均拒绝；实际候选WASM完成已有六场景，加包装后的四段99行合成传输，核逐片ACK和文件字节。合成字段名不作为实机字段名证据。真机完整接收、手表ACK、SAF和原件独立复算仍待；只安排用户更新手机后旧99条一次传输，不新采/删除/改配对，最终再合并DS。

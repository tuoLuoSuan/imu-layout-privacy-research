# S5普通数据传输设计

用户已授权“先方便传电脑，再测试功能，最后合并DS交接”，此前“有事自行决断”继续有效。用户报告0.3.0已更新、首页正常；这是用户反馈，不是工具回读或数据验收。旧2秒原件仍未收到，不假定被升级删除。Codex主智能体实施，不开子代理、不改冻结手机/旧手表版本。

## 路线取舍

优先复用已经连好S5的手机AstroBox2.2.0：手表主动发送→普通Interconnect接收插件→系统保存一份文本→USB复制到电脑核验。用户无需为首轮传输重新绑定手表。电脑有正常蓝牙适配器，但尚未装/连接桌面AstroBox；同一插件可作为后续桌面直接接收候选。配套原生Android接收器另需包名/签名条件且会新增APK，不作为本轮首选。二维码保留备用。

依据：官方Vela interconnect API；公开AstroBox插件WIT/模板和PluginSystem源码，实际核到注册包名接收、应用消息发送、插件私有WASI目录与系统保存文件接口。源码与接口可用不等于用户宿主已运行。接收注册只有原始消息字符串，不依赖未经核实的设备地址包装；插件只选择一个连接设备并只订阅项目包名。

## 协议和持久化

- 仅手动传已停止保存的会话，传输期间不能启动采集/切换记录。接收端不启动传感器、不删改手表文件，不任意读应用私有路径。
- `S5TX1` JSON携带会话/确定性传输标识、格式v2或legacy1、part/总part、字节偏移、整part长度/CRC、最多1024 ASCII字符。格式v2的part0仍是原始导出清单，后续是各文件；legacy1仅支持≤64KiB的旧单条JSON，超出保留QR路径。
- 一次只有一包在途；只有收到匹配传输、会话、part、CRC的应用层ACK才推进，系统send成功不当落盘成功。2秒超时，最多三次重发；断线/拒绝/超时明确失败，可手动重试，从接收端已有字节位置续传。
- 接收端仅写自己的私有目录，严格校验传输标识/序号/长度/偏移；保存后才ACK。重复消息必须逐字节相同，部分写失败后的重发只补未写后缀，冲突拒绝，配额有界。完整part验证CRC后才能进入下一part。
- 跨进程重试用同一确定性传输标识和不可变manifest，不把CRC当密码学身份。目录数据不会自动清理；接收端满额明确拒绝。
- 接收完成只表示按段保存，不表示科研质量通过。用户点系统“保存到文件”后输出兼容现有IMUS5/IMU9P解码器的文本；逐段生成，不把整个会话读入RAM。电脑端原独立检查器继续核清单、行数/序号、时间、缺尾和原始字段。

## 本轮可交付与真机门

新增0.3.1工作副本，只改导出UI/消息模块/版本与声明，不修改0.3.0核心行为；实际构建源码格式/同签名RPK和普通WASI插件.abp。工具链仅在.cache任务目录准备，不改全局PATH或需管理员的构建环境。

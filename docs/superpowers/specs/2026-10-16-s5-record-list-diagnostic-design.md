# S5 已保存99条但列表0/0：只读诊断

用户已授权主智能体自主完善与排错，本次不新增功能偏好确认，不开子代理。手机接收“已准备”、手表0.3.1显示已记录99／已保存99／可导出均为用户报告；没有实际文件或链路验收。写成功回调不证明文件可重新读出。

当前实现中，sealed 后才显示“可导出”；记录页再次通过 file.list(ROOT).fileList 枚举，以严格文件名识别会话。已有包、构建覆盖和官方文档已核，尚未取得本机原始列表返回，不认定具体 URI／字段是根因。

选择独立0.3.3/code7覆盖层，仅新增“文件检查（只读）”。直接读取同一应用目录的 file.list 与 file.get（recursive=false），分页显示返回类型、字段、数组数量及前几个原始 URI／name；失败、超时均可见。不扫描别的目录，不读取记录正文，不写入／删除／补索引／录制／自动传输。不把缺少fileList误报为空目录。当前采集、保存、恢复、协议、权限与旧包不改；继续沿用同证书、圆形图标、JS源格式。

替代方案：继续猜测URI归一化会改变查找／删除边界，证据不足；直接索取完整设备日志较繁重且现有应用没有打印列表返回。本轮只加诊断，拿到实际返回后才选修复。

检查期间阻止新采和导出；返回或离开页面作废旧结果。单接口8秒超时，晚回调不覆盖新页面。最多保留前8项字段／数组与前3项条目，每段字符串上限160字符，返回的大目录不复制全部。界面明确这是文件诊断，不是录制验收。

先用合成接口验证只读边界、异常形状、错误与超时，再验证实际暂存页面；旧99条不重录。构建后核ZIP、内容签名、同证书、原采集／传输字节与版本、旧源138文件及已知包摘要。手机采集66文件和r2保持。真机操作仅保留数据覆盖升级后点击一次文件检查，不启动新采；取得原始诊断前仍不称修复。

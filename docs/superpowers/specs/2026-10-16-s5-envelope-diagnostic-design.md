# S5 未识别消息的结构诊断

用户已授权主智能体自主排错。继续既定可观测性方案，不开子代理，不反复要求设计确认。

0.2.1手机自检通过为用户报告；三次传输后12/0/0/0，新宿主日志确认12个1167字节的JSON对象，没有根p或已知data包装。保存及回复均未进入。外层实际字段仍未知，不根据现象猜测payload/data/value或改CRC规则。历史原件、包与初始证据保持。

可选路径：直接猜解包会引入未证实规则；开启全量原始调试日志可能包含原始数据与账号字段；本轮采用受控结构诊断。独立api4-envelope-diagnostic/0.2.2只补根及两层结构摘要，字段名只允许固定词表，其余统一other，值只显示类型或明确协议常量，限制输入8192字节、摘要长度及递归深度。ignored保留摘要，UI和[S5RX]日志均能读到。字符串内JSON仅作有界结构观察，绝不交给接收核心。

原api4-observation/0.2.1和api4/0.2.0源包不动，新variant的receive.rs与0.2.1逐字节相同。沿用SDK0.4.0、API4/WASI3、原生async、插件名、received缓存、三普通权限。手机采集66文件/r2和手表0.3.4保持。

先测试ignored后包装结构仍可见，未知键和值不泄露，过大/深层输入有界，再跑实际组件五场景。诊断样例全部合成，不把合成包装当实机包装。包核验后仅安排用户保留数据覆盖手机插件，对已有会话一次试传并读取最近一步；原件、Android传输、SAF、分钟/息屏仍待验。取得明确结构后再做最小解包修正，最后合并DS。

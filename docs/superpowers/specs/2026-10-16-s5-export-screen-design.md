# S5导出期间保亮 / 0.4.5

用户在0.4.4一分钟录制后，报告导出时息屏会停止，明确要求优化；此前已授权自主完善。Codex主智能体执行，无额外审批或子代理。

## 原因与选择

录制startRecording请求brightness保亮，导出startWireless/openQrExport未请求；onHide取消传输以保留可解释前台边界。这一缺口与用户现象相符，未取得原生电源日志，不推定固件内部根因。

选择沿用普通system.brightness接口：蓝牙连接检查、读文件、发送及等ACK全程持有，收到最终ACK/失败/取消后释放；二维码展示期间保持，关闭/读取失败/离开页面时释放。保留onHide取消，不改为未经验证的息屏后台传输。不改系统超时，不加音频/定位/网络保活。

## 行为与边界

- 独立export-screen/0.4.5/code14继承0.4.4及同证书、源格式、圆标、四能力。录制/连续性/运输/列表模块保持，head仅版本递增。旧原件不改写，导出保亮观察不塞回已封口记录。
- 导出前先请求保亮，成功才列文件、检查连接或开始发送/展示；双击只一次。缺方法/fail/异常/3秒超时可见失败，不发送、不静默退回易息屏模式。
- 导出保亮与录制使用各自生命周期；pending和释放期间锁住新采集/重复导出，防止前一次释放关闭新操作的保亮。取消等待开启后，晚到成功不能开始传输，并沿用既有有界补释放。
- 蓝牙最终ACK表示接收端缓存确认，仍提示用户保存到手机文件；完成后即释放，不让成功页无限亮屏。失败/连接拒绝/连接超时/文件读取失败/取消/隐藏/销毁都释放。
- 二维码停留/分页/暂停播放均持有，返回记录/读取失败/隐藏/销毁释放。不会自动切回二维码或自动重传。
- 保亮释放fail/异常/超时在当前页可见，不能显示成正常清理。接口success仍不是屏幕电源实测。
- 不修改record/export字节、CRC、清单、分片、重试或ACK校验。完整原件和失败数据保留。

## 验证与交付

真实staged页面红测：旧版开始传输没有brightness请求；新模式先保亮再发送，任一段ACK期间不能释放，最终ACK释放。覆盖请求失败/缺接口/超时、重复点击、取消/晚回调、连接未就绪/检查超时、读文件失败、发送失败、隐藏销毁、释放失败、二维码完整生命周期及新采集互斥。复用传输核心验证往返字节不变。

先本机测试、实际RPK/签名/源输入、277保护及14原件3896行核对，再源码白名单私有备份/取回/CI与分发文件SHA。用户保留数据覆盖更新，先首页/退出，再仅重传已有一分钟999条，手机前台接收、手表不触屏，观察超过原息屏点后是否持续到完成及之后恢复息屏；接收文件与旧原件逐字节核对。不为验证另采一条。

0.4.4一分钟原件仅支持该轮60秒high通用前台录制分项，不等于导出保亮、五分钟、自然后台、硬件Hz、单位轴向或同步通过。

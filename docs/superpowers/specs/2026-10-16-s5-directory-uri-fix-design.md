# S5 目录URI兼容修正

继只读诊断，用户提供两张0.3.3真机照片：file.list为object、fileList共20项，首个旧版记录URI明确为internal://files//…（files后两条分隔符）。照片带定位水印，仅私有归档，不转录定位。尚未直接看到新v2头文件或99条正文。

旧核心移除internal://files/后留下前导斜杠，严格s5r头文件正则失配。此格式缺陷已与实际返回对应；先用相同格式的合成99条记录证明旧列表0条，再验证新列表／inventory／读取字节，最终仍需真机确认。

选择独立0.3.4/code8覆盖0.3.3暂存，不改旧源／旧包／手机66／r2。新增directory-entries.js，仅在file.list边界转换URI：接受原有bare basename、标准internal://files/name和本机观察到的internal://files//name；同一文件多种表示去重。只去掉已确认的一个额外根目录分隔符，拒绝别的scheme、绝对路径、目录项、路径穿越、编码分隔符、反斜杠和更多层斜杠。不用basename任意剥路径，不重命名／重写／补录原文件。

目录结果必须是数组，未知形状显示错误，不再静默当空目录。原核心的list、inventory、数量门、trash/restore/purge共用这一个边界，因此均得到同一套规范化结果；既有allowedName仍是读／删路径最终门。诊断页继续显示原始返回，不用规范化后的数据冒充原始URI。旧记录metadata不改，只有以后新记录版本号0.3.4。

测试先红后绿：旧99条在双斜杠列表0条→新实现列出／导出99，全部原文件字节相同；混合URI去重；恶意路径不读取／删除；40条容量门不绕过；指定会话回收／恢复／删除不触碰其它会话。实际RPK核内容签名、同证书、版本／能力／格式、旧源与包摘要。无新界面设计，沿用已检查的0.3.3模板，仅版本改变。

用户仅保留数据覆盖升级后查看已有记录，不重录／删除；有记录再按既有导出入口发旧记录到已准备的手机接收端。取得TXT原件前不声称原件／持续性／真实链路通过。DS仍在链路功能后合并审查。

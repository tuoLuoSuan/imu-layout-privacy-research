# S5文件传输实施计划

目标：一条普通消息链路导出完整会话到手机/电脑文件，减少二维码拍摄。当前聊天由主智能体执行；用户已委托具体选择，不启动子代理。

1. 固定公开WIT/插件宿主/模板源码提交与工具版本，检查消息载荷和文件保存接口；仅.cache内构建工具，不运行设备命令。
2. 先写`collection/watch-s5-probe/tests/transfer.test.cjs`，验证发送单包、丢ACK重试、错误ACK拒绝、恢复推进和取消；实现独立`variants/research-transfer/src/common/transfer.js`。
3. 新`collection/astrobox-imu-receiver`：Rust纯接收核心按包落盘、校验和恢复，CLI合成测试与WASI宿主适配分离。先失败测试再实现；Host只调用device/register/interconnect/dialog/ui，不使用固件/transport/安装/启动应用功能。
4. 0.3.1导出选择页接入发送模块，保留旧QR/旧数据只读入口与所有采集逻辑；版本身份在暂存构建时更新，旧源/包不改。
5. 生成合成JSON传输消息，经实际Rust核心接收、导出兼容文本，再由独立Python复算原件；覆盖失败/重启和5分钟文件集，不冒充真实蓝牙吞吐。
6. 构建同签名0.3.1与.abp，校验实际包内容/权限/源码格式/图标，检查真实模板布局；精确白名单源码备份，不上传原始数据/密钥/包/截图。
7. 到用户实际操作时，先装接收插件并确认准备接收；只发送既有2秒原件。该链路通过后再做新采/记录管理短试；最后合并DS交接。用户未操作时不报告真机通过。

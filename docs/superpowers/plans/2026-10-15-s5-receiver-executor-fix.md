# 接收插件异步执行边界修正

用户0.1.1本地点击通过，准备接收停在同步写入的“查询设备”且无后续反馈；不改配对/权限或手表包。本轮由主智能体自主执行，不开子代理。

1. 冻结本次用户观察。核实际SDK：WIT回调是返回future的同步func；默认生成同步导出；spawn只排队，需已有executor。现有组件没有async-lift/callback导出。用实际旧ABP做失败检查，另以SDK做本机排队最小复现。
2. 增加独立二进制ABI检查及截断/伪字符串等测试，检查四个回调均存在真正的异步任务入口和继续执行入口，而不是搜索WASM中的字符串。
3. 仅按MIT许可保留与SDK0.3.1对应的WIT接口和许可证；用相同wit-bindgen0.57.1显式异步导出四个回调，复用SDK导入类型，生命周期和普通权限不变。使现有spawn在真实导出任务内被驱动，不以阻塞writer造成死锁。
4. 0.1.2保留浅色/旧缓存/协议和手表版本；界面检查同步反馈后执行一次无需设备的yield，报告运行检查通过，先验执行器，再试设备查询。未完成不能假报接收准备成功。
5. 本机测试、实际组件ABI检查、合成数据往返、源文件保持与私有备份。打包不通过ABI检查则拒绝交付。原0.1.0/0.1.1及手表包不覆盖。
6. 用户先覆盖更新手机插件，仅点一次界面检查；如运行检查不通过，停止继续尝试变体，取普通宿主诊断/评估替代普通出口；真实蓝牙及原件保持未验。链路和功能后再合并DS。

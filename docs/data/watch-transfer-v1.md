# 腕部普通消息传输协议 S5TX1

这是导出运输层，不改变[腕部schema2](watch-s5-v2-data-dictionary.md)或旧schema1的原始字段。

| 字段 | 约束 |
|---|---|
| p | `S5TX1` |
| t | 16位小写十六进制；由格式/会话/part数/part0内容确定的恢复标识；不是身份认证 |
| s | 会话ID，1–80个ASCII字母/数字/下划线/连字符；下游仍核具体数据合同 |
| m | `v2`或`legacy1` |
| i / n | 当前part从0起，part总数1–403；legacy1只允许n=1 |
| o / l | 当前ASCII字节偏移／完整part字节数，l为1–65536；不允许越界或跳过未存部分 |
| c | 完整part的CRC32，8位小写十六进制 |
| d | 本包原始ASCII片段，1–1024字符；保留JSON转义，不重写原始XYZ |

v2：part0仍是包含文件顺序的导出manifest，其余part与列表一一对应。legacy1：part0为原schema1完整JSON，超过64KiB明确拒绝此快速路径，保留旧二维码方案。两种格式不会相互改写元数据。

匹配的成功确认：`{p:S5ACK1,t,s,i,o,c,state}`。o表示接收端保存后已连续获得的字节数；state为stored或part_complete。完成段必须验证CRC，最后一段还核全部段存在/CRC与manifest身份。接收端可在匹配重复请求后报告已有更长前缀，发送端据此恢复。源文件或元数据冲突明确拒绝，不能覆盖旧接收记录。

失败确认：`{p:S5ERR1,t,s,error}`。发送端只接受匹配本次会话/传输的确认，其他普通消息不解释成命令。系统send成功不是文件已存的证据；2秒未获确认最多重发3次，然后显示失败。连接状态查询另有8秒软件超时；用户重试而非无限后台重连。无硬件单调时钟保证，计时检测到倒退则失败。

接收端每条≤16MiB、最多32条，独立part文件≤64KiB；有冲突/CRC坏段保留证据，不自动清理。写入后sync成功才ACK；这不证明手表采集质量或全部底层硬件已完成物理落盘。插件私有缓存与最终系统保存TXT分开，用户还需完成文件保存。

最终输出逐段重新封装为兼容IMUS5/IMU9P的文本，原part内容逐字节保留，继续使用独立Python核清单/序号/行数/时间/缺尾等。CRC不是加密，普通配对和用户手动导出不证明攻击者自动出口。电话/电脑宿主、SDK消息JSON包装、最大可用消息量与实际吞吐均以真机短试为准，本机593条合成消息不当蓝牙性能结果。

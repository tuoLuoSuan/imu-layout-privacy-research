# 实际组件的收包与文件系统门

这是项目自有的最小宿主，继承旧API4 UI测试方法，增加wasmtime-wasi48.0.2真实p2/p3实现及受限合成目录。不是AstroBox Android宿主，也不包含／链接其AGPL实现。

真实文件接口先注册，再显式注册四个系统保存失败桩；不使用全局未知导入填充去替换已注册的WASI资源。初始本机原型在未知导入填充时出现pollable类型失配，已在此宿主修正；不把测试宿主错误当作手机或插件根因。原0.2.0 ABP嵌入组件也已在同一真实文件系统方法下跑通合成事件／保存／确认／重复包，原件未改。

五场景使用独立新目录，不接触既有received缓存或真实设备：

- 成功：忽略未支持的data对象包装，再收标准包和重复包，验证原正文与两次确认。
- 注册拒绝：两次注册均失败，后续事件没有文件写入或回复；错误仍可见。
- 查询等待期间重复点准备：只有一次查询与注册，后续收包仍能工作。
- 回复API拒绝：原文件字节保存，但回复提交计数保持0、错误可见。
- 四段v2：99行合成回调、按1024字符分片；每次确认偏移／段号正确，四段原文件逐字节相同。

SDK UI仅收集实际渲染文本，不验证Android像素布局；系统保存被刻意设为失败桩，触发会使本门失败。组件以wasm32-wasip2构建、接口为API4原生async。所有普通宿主接口均为合成替身，不构成蓝牙吞吐、单位、硬件时间、功耗、持续性或真实权限验收。

运行父目录tools/build_local.py；构建器会先跑共享9测试与观测4测试，再编译实际组件／此宿主，并为每场景生成不存在的新目录。本机缓存文件不是科研原件。

0.2.2另有structure-only场景：12个合成未知包装保留12/0/0/0与结构提示，无received目录，无S5ACK1回复；两次prepare的两个S5HELLO1不算确认回复。包装字段仅合成，不证明实机格式。

# 旧软件怎么整理

今后的实验只打开手机IMU联合采集＋AstroBox内IMU联合时间桥＋表IMU联合采集，均0.2.2。本次补长档需三件覆盖，手机原圆角方标保持；不卸载任何有旧记录的应用。

| 原入口 | 这次处理 | 历史记录 |
|---|---|---|
| 手机IMU联机采集0.1.1／联合采集0.2.0 | 直接覆盖为IMU联合采集0.2.2，同 `org.imulayout.jointprobe` | 原已封口手机记录继续由同一应用读取 |
| 表IMU联机检查0.1.0 | 直接覆盖为IMU联合采集0.2.2，同 `org.imuresearch.s5joint` | 同身份更新；本次已到电脑的原件保留，未逐条验证所有表内旧文件 |
| 插件IMU联合时间桥0.1.0 | 先导出要留的日志，再同名覆盖0.2.2 | AstroBox可能替换整个插件目录，不保证插件内旧列表保留 |
| 手机旧IMU采集0.2.2 | 不再用于新实验，先保留作历史入口 | 与新App私有目录不同，未自动迁移；未核齐旧记录前不卸载 |
| 表旧S5活动采集0.4.15（`org.imuresearch.s5probe`） | 不再用于新联合实验，先保留作历史入口 | 表内可能有尚未全部备份的历史记录，不能一键清掉 |
| 插件IMU腕部接收0.2.5 | 停用作新实验入口；需要救旧S5记录时再用 | 仍可用于旧格式的历史导出，不混用新会话 |
| 插件/表IMU时钟检查 | 专项检查已结束，不再用于新实验 | 保留需留日志后再由用户移除 |
| 表S5能力核查 | 核查已结束，不再用于新实验 | 需要保留的声明JSON先存好，再由用户移除 |

“停用”指今后不再打开它采新数据；不等于软件已经被卸载。本轮没有替用户卸载、禁用或清数据。旧App不能访问彼此私有目录，因此不能凭“电脑已有一些文件”断言所有历史记录都已备份。

建议只把新的两个“IMU联合采集”放在手机和表的常用位置，AstroBox只打开一个IMU联合时间桥插件。等历史记录逐项核齐，再处理旧入口；后续同身份更新，不再增加新的安装图标。

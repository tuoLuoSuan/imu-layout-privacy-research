## 有线首次短试

1. 用户用原数据线连接电脑，允许普通USB调试，保持屏幕解锁。Codex重新确认设备与本APK的SHA256后安装，不启动旧记录器或改其设置。
2. 用户打开“IMU采集”、允许通知，点开始。确认计数增长与通知存在。Codex读取本包UID/PID及真实服务；启动异常就先处理，不盲目开始长试。
3. 前台亮屏60秒 → 其他App亮屏60秒 → 系统锁屏90秒 → 回前台30秒。用户每个阶段开始后报告已完成操作，保留实际操作区间；锁屏阶段不解锁看时间。
4. 四阶段分别取只读快照；每轮重读本包UID/PID。示例命令中的设备序列号要替换为本轮实际识别值：

```powershell
& 'D:/Project/imu环境重建/collection/phone-imu-recorder/tools/capture_state.ps1' -Serial '本轮实际设备序列号' -OutputDir 'D:/Project/imu环境重建/environment/reports/native_short_wired_001' -Phase foreground
```

其余Phase为other_app、screen_off、returned。脚本保存package、services、sensorservice、UID状态、power、设备墙钟/uptime及每条命令的主机起止。输出只在本机；串行快照不证明整个阶段状态或冻结完整因果链。通知存在性由用户另作简短确认，不截取无关通知。

5. 用户停止并等收尾，导出原ZIP。Codex保存原样副本/哈希，独立检查与外部快照对应。任何>1秒缺口、计数/失锁/前台服务条件失败，先保留证据定位，不直接重录半小时。

## 拔线与长试

有线通过后，拔线重复同一短协议，分开报告供电条件。此时无当时ADB快照，只能报告导出连续性和实际已观察状态，不能称全程 externally observed 或把有线状态直接推广。

两次短试通过后，做前台5分钟 → 锁屏10分钟 → 其他App亮屏10分钟 → 回前台5分钟。若切换时间偏移或中途解锁，照实记录。45分钟上限/30秒收尾已由假时钟覆盖逻辑，不等于已经做过45分钟物理测试。

验收原件放data/raw/phone对应独立session，报告放environment/reports。应用正常结束、内部data_checks_passed、独立检查、真实服务观察和论文输入门槛分别报告。当前不开展HAR训练、手机/腕部时间拟合或雷达联采。

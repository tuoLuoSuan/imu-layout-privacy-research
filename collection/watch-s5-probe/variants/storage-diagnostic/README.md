# S5 0.3.3：只读文件诊断候选

用户报告0.3.1结束后已记录99、已保存99、可导出，而记录页0/0。当前只确认页面反馈，尚未收到S5原件；不能认定数据丢失，也不能认定文件可重新读出。

本版本在保留的0.3.2暂存副本上新增记录页“文件检查（只读）”，用现有system.file权限顺序调用同一目录的list与get（recursive=false）。分页显示返回字段、数量及前三个条目的原始uri/name，保留未知返回形状；每接口8秒超时，失败可见。路径只用于展示，不拿诊断返回去读写文件；诊断不采样、不写入／删除、不补索引、不发消息。显示换行不改变原始URI。

这不是列表问题的修复包。已有采集／存储／旧记录恢复／传输核心与协议保留，仅导出的新记录版本号随应用升级。旧0.3.1、0.3.2与手机采集0.2.2源码／包均不改。继续沿用圆形图标、minAPI2／designWidth466、普通三功能和同一本地签名，不使用JSC／Protobuf。

```text
node --test collection/watch-s5-probe/tests/*.test.cjs
node collection/watch-s5-probe/tools/build_storage_diagnostic_source.cjs
```

构建输出要求是模块dist下不存在的新目录，旧包不覆盖。最终分发候选以协议顶部记录的SHA为准；首次离线候选有长URI裁切，未分发，保留在dist/storage-diagnostic-0.3.3。最终候选在dist/storage-diagnostic-0.3.3-r2，实际模板静态预览与真机渲染分别说明。

用户下一步只需保留数据覆盖升级，确认0.3.3，进入记录→文件检查；先提供第一、第二页。不要新录、移回收区、永久删除、清数据或解除配对。取得目录真实返回后再决定修复。手机接收插件保持已有已准备状态，分钟／息屏／真实传输继续待验。

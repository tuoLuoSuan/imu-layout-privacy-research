# S5导出文件等待退出 / 0.4.6

本版继承0.4.5导出保亮，给蓝牙和二维码的目录/分片读取分别增加8秒工程等待上限。它沿用项目已有文件写入/连接检查的等待量级，尚非由S5成功读取耗时分布标定的上限，也不是科研筛选门。整个JS循环挂起时，JS计时器不能提供外部守护。

超时可见失败，走既有释放路径，原记录保留且不自动重试。每次文件调用分别计时；QR已经显示后可持续查看/暂停，不限制整页或整段传输时长。ACK重试保持原策略。取消/隐藏/销毁清理文件等待，迟到结果不能覆盖新页面；QR读取错误与释放错误分别保留。

保留获取/释放/已观察迟到补释放的串行屏障。过早用Promise.race放行下一次操作，旧请求的迟到补释放可能关闭新操作的保亮；没有采用该方案。接口超时不证明物理屏幕已经关闭，未知固件无界迟到也不能靠本机定时器排除。

采集、屏幕guard、连续性、目录及传输模块不变；仅新profile页面和版本变动。导出等待观察在页面内存_lastExportScreen.file_wait中，不写回已封口记录，重传0.4.4原件仍保留0.4.4元数据。四普通能力、源格式、圆标和同签名保持。

目前是离线候选，无本版真机启动/录制/导出证据，物理设备仍为用户确认的0.4.5。用户暂停设备操作期间不安排安装或传输。日后恢复步骤见docs/protocols/2026-10-16-s5-export-file-wait-first-run.md；先启动，再重传旧999条，不要求新录制。
